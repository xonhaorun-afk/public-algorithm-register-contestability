# 验收标准 v2

## 版本目的

v2保留v1的52项研究完整性检查，并针对GitHub交付修订论文哈希、图片链接与原始快照恢复方式。v1文件及历史运行日志不覆盖。

## A. 本地研究完整性

沿用`verifier/v2/verify.py`的52项自动检查，包括：

1. 当前快照1,608行、1,608个唯一标识、346个机构；历史快照3,035行、1,629个标识。
2. 六项全站覆盖计数、人工复核62条、17条真阳性与5条假阳性。
3. 539个同一1.0标准配对、McNemar方向与精确p值。
4. 敏感性、机构等权、跨标准描述和聚类模型的关键结果。
5. 五张PNG尺寸、SVG存在及论文数字、章节、引用和解释边界。
6. 修订后论文SHA-256为`07a8a064c84ad5faef62f3ef85e6887bfe50ae0767ebe2cc47ba49d4fbf2910f`。

通过条件：52／52检查通过，退出码0；日志追加至`verifier/runs/`，失败记录同样保留。

## B. 固定快照恢复

1. `python3 analysis/restore_archive.py`必须从两个官方公开接口恢复CSV。
2. 当前文件SHA-256必须为`062550033289976baa6ee2b75a923c991c984e4ccf9d676297b434a374aad01f`。
3. 历史文件SHA-256必须为`83d3cbafb93146c5c39fead5cb8de2ba75c859e24d0e5120c56d4f5115daf54f`。
4. 哈希不一致时脚本必须失败，不得把新实时文件冒充为论文归档。

## C. GitHub远端交付

使用独立的`verifier/v2/remote_verify.py`读取GitHub原始文件，而非依据上传操作的成功回执推断完成。检查：

1. 论文、README、数据字典、来源清单、分析代码、人工复核表、统计输出和验收历史可公开读取。
2. 论文只引用五张已入库SVG，不再引用远端缺失的PNG或原始CSV路径。
3. 五张SVG均为可解析XML，并包含对应图题或核心数据文本。
4. 恢复脚本、本地论文、README和核心统计输出与远端逐字节一致。
5. 官网两个接口仍返回规定哈希；若未来官网变化，记录为快照恢复阻塞，不伪造通过。
6. 核验结果写入`verifier/v2/remote_acceptance.json`与`verifier/runs/`；上传核验报告后，再读取报告本身确认公开可访问。

## D. 解释边界

远端验收只证明交付文件、恢复路径和研究结果一致，不证明实际救济有效、联系方式可连通、算法合法或登记册覆盖政府全部算法。GitHub网页版直接展示SVG；PNG和条目级处理数据由本地复现生成，不声称它们已作为二进制或大文件入库。
